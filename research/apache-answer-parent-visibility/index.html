A hidden question should stay immutable

Apache Answer checked that mutation targets existed but did not consistently verify that the caller could see their parent content. Version 2.0.3 restored the missing authorization boundary.

By Luigi Colluto · Resolved upstream 9 October 2026 · Published 28 October 2026 · 3 min read

What went wrong

Apache Answer can keep questions and related content non-public while they are hidden or pending moderation. Read paths applied that visibility model, but several mutation paths asked a narrower question: does the requested object exist and has it not been deleted?

That check was not enough. The services that added answers or created comments, votes and reports did not consistently call the shared visibility check for the target object or its parent question. An ordinary authenticated user who knew an identifier and met the feature's normal rank requirement could therefore act on content the same account was not permitted to view.

The bug did not remove every authorization rule. Rank thresholds, authentication and object-state checks still ran. The missing layer was contextual: before changing a child object, the service also had to establish that this principal could operate on the content graph containing it.

Why it mattered

Apache's announcement rates the vulnerability Moderate and lists versions through 2.0.2 as affected. It required an authenticated user and knowledge of a target identifier; it was not an unauthenticated path and did not bypass the platform's ordinary rank thresholds.

Within those conditions, the caller could create visible side effects around non-public content. Depending on the operation, that could include adding an answer or comment, changing a vote, filing a report, updating scores or causing related activity and reputation events.

The core integrity problem was the mismatch between reading and acting. Content hidden for review or moderation should not remain mutable through a lower-level endpoint merely because its database row can be resolved.

How it was fixed

The public repair routes the caller's identity and administrator-or-moderator state into the affected services. Before an answer is inserted or a comment, vote or report is created, the service now calls the common visibility check on the target content.

For a new answer, the patch reconstructs the relevant question context — its author, status and visibility — and applies the same rule before continuing. For the other mutations, it checks the resolved object before decoding identifiers or writing side effects. Administrators and moderators retain the elevated access expected by the existing visibility model.

The fix was released in Apache Answer 2.0.3 on 9 October 2026. Apache's public announcement credits Luigi Colluto as the reporter and recommends upgrading from affected versions to 2.0.3.

After the patch

Existence is not authority. A successful lookup proves that a row is present; authentication proves who is asking. Neither proves that the caller may change that object in its current context.

This matters whenever an API mutates a graph rather than an isolated record: comments belong to posts, answers to questions, attachments to issues and reactions to messages. Review each mutation from the parent boundary outward. If the parent is hidden, pending, locked or outside the caller's tenant, every child operation must preserve that state before it produces a side effect.
