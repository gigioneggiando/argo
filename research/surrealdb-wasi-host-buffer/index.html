A guest memory limit does not cover host buffers

SurrealDB limited a module’s guest memory but buffered its unfinished output in unbounded host memory. A module could therefore exhaust the database process outside its configured ceiling.

What went wrong

SurrealDB’s experimental Surrealism runtime executes WebAssembly modules through Wasmtime and places a ceiling on the guest’s linear memory. That limit covered memory allocated inside the module, but the host also created resources on the module’s behalf.

The WASI stdout and stderr callbacks collected an incomplete line in a host-side Vec until they encountered a newline. A module could repeatedly write bytes without ever finishing the line. Each write remained within the guest’s own memory budget, while the pending output grew in the SurrealDB process outside Wasmtime’s store limiter.

The mismatch sat at the callback boundary: a constrained guest controlled how much state an unconstrained host-side consumer retained.

Why it mattered

A malicious or faulty module could keep extending that newline-free output until the host exhausted memory and the database process became unavailable. This did not escape the WebAssembly sandbox or expose data; the demonstrated consequence was denial of service.

Surrealism was experimental and disabled by default. Installing a module required an Owner-level user, which narrowed initial exposure. Once a module was installed, however, users permitted to invoke its functions could trigger the behaviour, and module function permissions defaulted to full access. The resource belonged to the host process, so one module could affect service for other users and namespaces.

The advisory rates the issue Medium. It covers SurrealDB 3.1.0 up to, but not including, 3.3.0, and surrealism-runtime 0.3.0 up to, but not including, 0.6.0.

How it was fixed

The repair added a one-mebibyte ceiling for each pending line. When output reaches that threshold without a newline, the callback emits a chunk to the log and continues instead of retaining the entire stream. The implementation also respects UTF-8 boundaries, so bounding memory does not require dropping or corrupting output.

The public regression tests exercise both guarantees: the internal pending buffer stays bounded, and all bytes are eventually emitted. The fix was committed on 7 September 2026 and shipped in SurrealDB 3.3.0 together with surrealism-runtime 0.6.0.

After the patch

A sandbox limit is only as complete as the resources it counts. Guest memory, instructions and execution time may be bounded while logs, response buffers, caches, queues or file descriptors allocated by the host remain unlimited.

The useful review question is therefore broader than “how much can the guest allocate?” It is “what can the guest cause the host to retain?” Every callback that converts untrusted guest activity into host state needs its own lifetime and budget. Here, a small cap at that boundary made the configured memory ceiling meaningful again.
